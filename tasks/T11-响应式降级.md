# T11 · 响应式降级

**状态**：待做　**优先级**：P2　**平台**：双　**依赖**：T04　**预估**：1 人日

## 目标

1280 / 1080 / 860 / 760 / 480 五档都能用，任何一档都不出现横向滚动条。

## 断点表

| 宽度 | 变化 |
|---|---|
| ≥1080 | 完整（列表 + 340 详情） |
| <1080 | 隐藏详情面板（Web）；操作转右键菜单 |
| <960 | GTK 隐藏详情面板（唯一断点） |
| <860 | 筛选条横滑；状态栏中部键位提示隐藏 |
| <760 | 元信息只留大小（隐藏相对时间）；路径只留末级 |
| <560 | 应用条只留标识与设置 |

## 改动点

### Web

1. `@media (max-width:1080px){ #preview{display:none} .stage{grid-template-columns:1fr} }`
2. `@media (max-width:760px){ .tm{display:none} .meta{width:auto} .row{grid-template-columns:20px minmax(0,1fr) auto} }`
3. `@media (max-width:860px){ .st-hints{display:none} }`
4. `@media (max-width:560px){ .tb-mark .tb-ver{display:none} }`
5. 现有的 `<720px` 规则合并进新断点，避免两套并存。

### GTK

1. `on_configure` 里按宽度切 `self.preview.set_visible(width >= 960)`，只在跨越阈值时切换（用一个 `self.wide` 缓存）。
2. 窗口最小宽度设为 480（`set_geometry_hints`），避免被拖到不可用宽度。
3. 元信息列宽 116 固定，窄窗口时列表自然收缩，不做二次降级（GTK 很少 <600）。

## 验收

- [ ] 五档宽度截图，`document.documentElement.scrollWidth <= innerWidth` 全部为真
- [ ] 1080 以下详情面板消失后，列表占满宽度，行不被拉伸变形
- [ ] 760 下时间列消失，但大小仍在；tooltip 或详情里仍能看到时间
- [ ] 480 下应用条只剩标识与设置，搜索框仍可用
- [ ] 缩放到 200% 时不破版（等价于 640 宽）
- [ ] GTK 拖动窗口从 1200 → 800，详情面板在 960 处消失，列表自动补宽

## 风险

- 断点用 `max-width` 时注意与现有 `<720px` 规则叠加顺序（后写的覆盖前面的）。
- 隐藏 `.tm` 后行高不变，但 `.meta` 只剩一行会垂直居中偏移，需要 `align-self:center`。
- 不要在 `size-allocate` 里做重布局（每帧触发），只在阈值跨越时做。
