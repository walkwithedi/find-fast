# T05 · 状态栏与扫描进度

**状态**：进行中　**优先级**：P0　**平台**：双　**依赖**：T01　**预估**：0.5 人日

## 目标

全界面只有一处报数。扫描进度改成搜索框下缘 2px 的流动条，不推动任何布局。

## 为什么

`#status` 报「N 个结果」，页脚 `#index` 报「共 N 个条目」，两个数字长得像但含义不同；GTK 侧是左右两个 label。扫描时替换整行文字会让列表整体下移 1 行高。

## 改动点

### Web

1. 删除 `#status` 元素与 `setStatus()` 对它的写入；页脚 `<footer>` 换成 `.statusbar`：

```html
<footer class="statusbar" role="status" aria-live="polite">
  <span class="st-count" id="count"></span>
  <div class="st-hints">…↑↓ 选择 / Enter 打开 / Ctrl Enter 定位 / ? 快捷键…</div>
  <div class="st-right"><span class="dot"></span><span id="indexState"></span></div>
</footer>
```

2. 新增 `#progress`（搜索框下缘，`position:absolute; height:2px`），`class="on"` 时显示，扫描结束移除。
3. `showCount(ms)` 改为写 `#count`：`<b>7,204</b> 个结果 · 12 毫秒`。
4. `showIndex(st)` 改为写 `#indexState`：`实时更新 · 共 128,441 项`；异常时换 `--warn`/`--bad` 与对应文案。
5. 删除页脚原来的 `#rule`（关闭说明），它的文案移到「更多」菜单的「关于」。

### GTK

1. `self.status` 与 `self.state` 合并：左侧 `st-count`（`N 个结果 · X 毫秒`），右侧 `dot + 状态`，中部键位提示（`<860px` 隐藏）。
2. 扫描进度：`Gtk.Overlay` 包住搜索行，底部对齐放 `Gtk.ProgressBar`（class `scan`），`set_overlay_pass_through(True)`；扫描时 100ms `pulse()`，结束 `hide()`。
3. 删除扫描时替换整行文字的 `set_status('scanning')` 路径（改为状态栏右侧文字 + 进度条）。

## 文案

| 键 | zh | en |
|---|---|---|
| `results_ms` | `{count} 个结果 · {ms} 毫秒` | `{count} results · {ms} ms` |
| `scanning_short` | `正在更新索引：{dirs} 个文件夹，{files} 个条目` | `Updating the index: {dirs} folders, {files} entries` |
| `entries` | `共 {count} 项` | `{count} entries` |
| `ready` | `就绪` | `Ready` |

## 验收

- [ ] 全页面 `grep -c "个结果"` 只在状态栏出现一处
- [ ] 扫描开始/结束，列表顶边的 `getBoundingClientRect().top` 不变
- [ ] 进度条 2px，颜色 `--accent`，动画 1.2s 线性循环
- [ ] 扫描中仍可输入、可选中、可打开
- [ ] 错误消息 5 秒后回到常态文案
- [ ] 760px 宽时中部键位提示隐藏，计数与索引状态保留
- [ ] GTK 状态栏高度 28，单行不换行

## 风险

- 状态栏用 `role="status" aria-live="polite"` 时，每次输入都会触发播报。**只在结果数变化时更新文本**，`ms` 部分用单独节点或延后合并，避免刷屏。
- GTK 的 `Gtk.ProgressBar` 默认有最小高度与圆角，必须用 CSS 强制 `min-height:2px; border-radius:0`，否则会出现 6px 的条把布局顶开。
