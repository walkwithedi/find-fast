# T07 · 空状态三态与错误提示

**状态**：待做　**优先级**：P1　**平台**：双　**依赖**：T03　**预估**：1 人日

## 目标

三种「没有结果」各有出口，而不是留一张空表。语法错误就地解释，不占用结果区。

## 为什么

Web 版无结果时只剩表头；GTK 只有一句居中的 `no_match`。用户分不清「没这个文件」「词写错了」「索引还没建好」。

## 三态

| 态 | 触发 | 内容 |
|---|---|---|
| 起始 | 查询为空 | 图标 + 「找一个文件」+ 一句说明 + 3 个示例 chip |
| 无匹配 | 有查询、结果 0 | 回显查询词 + 出口按钮（清除搜索 / 查看语法 / 取消筛选） |
| 载入中 | 索引未就绪 | 6 行骨架 + 状态栏「正在载入索引……」 |

规格见 `docs/04` 第 8 节。

## 改动点

### Web

1. `#empty` 元素（在 `#rows` 之外，`.listwrap` 内），三种内容由 `emptyState(kind)` 生成。
2. `search()` 结束时判定：`!q` → `start`；`count === 0` → `nomatch`；索引未就绪 → `booting`；否则隐藏。
3. 示例 chip 点击：填 `#q` → `search()` → 焦点留输入框。
4. 无匹配时若 `type !== 'all'` 或 `scope`，说明改为 `当前有类型筛选：文档（5）`，按钮加「取消筛选」。
5. 正则语法错误：`/api/search` 返回 `error`，在搜索框下方 24px 处显示 `#qError`（绝对定位，`role="alert"`），**不**进入无匹配态。

### GTK

1. `self.empty` 从 `Gtk.Label` 换成 `Gtk.Box`（纵向，`valign=CENTER`，`halign=CENTER`，class `empty-state`），放进 `Gtk.Overlay`，`set_overlay_pass_through(False)` 才能点按钮。
2. 复用同一 `emptyState(kind)` 逻辑（Python 版），三种内容与 Web 一致。
3. `apply_layout()` / `after_refresh()` / `run_search()` 三处更新可见性。
4. 正则错误：搜索框下方显示一行 `--bad` 文字（`Gtk.Revealer` 展开），不覆盖列表。

## 验收

- [ ] 首次打开（无查询）显示起始态，3 个示例可点，点了立即出结果
- [ ] 搜 `zzzz` 显示无匹配，回显 `zzzz`，按钮可用
- [ ] 有类型筛选时文案切换为「当前有类型筛选：…」，「取消筛选」能清掉 type 与 scope
- [ ] 索引未就绪时显示骨架，不显示「没有匹配」
- [ ] 三种状态互斥（切换时上一个完全消失）
- [ ] 正则错误（`regex:(`）在输入框下方提示，列表保持上一次结果不变
- [ ] 空状态覆盖列表区，但**不遮挡**筛选条与状态栏
- [ ] GTK 空状态按钮可点击（overlay 不穿透）

## 风险

- 空状态的 `position:absolute; inset:0` 会盖住滚动条，需要 `right:11px` 或放在滚动容器内。
- GTK `Gtk.Overlay` 默认穿透子控件，必须显式 `set_overlay_pass_through(box, False)`。
- 不要在每次按键都重建空状态 DOM（会丢焦点），只在 kind 变化时重建。
