# T06 · 筛选条：类型、计数、范围收敛

**状态**：待做　**优先级**：P1　**平台**：双　**依赖**：T03　**预估**：2.5 人日

## 目标

大结果集不再只能滚。给出两条收敛路径：按类型（带全量计数）、按目录（结果 >400 时给两个建议）。排序从表头搬到右侧菜单。

## 为什么

v0.6.0 只有排序，没有任何缩小范围的入口。搜 `jpg` 出来几千条时，唯一动作是滚动或改搜索词重来。

## 关键决策：过滤必须服务端做

前端只有已加载的 200 行，按它算计数会差几十倍。因此：

- `/api/search` 新增 `type`、`scope`、`sid` 参数；
- `facets` 由服务端对**全量结果**统计一次；
- `type/scope` 的变化通过 `sid` 复用同一份结果，只重建视图（不重跑搜索，避免版本标签闪烁）。

详见 `docs/06` 6.2/6.3。

## 计数与建议的规则

- 8 个分类键，永远返回（含 0）：`all/folder/doc/image/archive/code/audio/other`。
- `audio` 含 video（`category_group('video') == 'audio'`）。
- `facets.all = n`（全量），`count` = 当前过滤后的数量。
- 「其他」chip 仅在计数 >0 时渲染；其余 chip 始终渲染（0 计数置灰），保证位置稳定。
- `scope_suggest`：`facets.all > 400` 且未设 scope 时给，最多 2 项，按二级目录聚合，降序。
- 选 scope 后 `type` 重置为 `all`（避免两个条件叠加后 0 结果让人困惑）。

## UI 规格

见 `docs/04` 第 3 节。要点：

- chip 高 28，`[标签 计数]`，选中 `--accent-soft` 底 + `--accent-ink` 字；
- 范围 chip 带文件夹图标与 `×`，`title` 为完整路径；
- 右侧排序按钮固定（`margin-left:auto`）+ 向左柔和投影，提示可横滑；
- 整条在无查询或无结果时 `display:none`（不留空白）。

## GTK 实现

- chip 条用 `Gtk.Box`，8 个 `Gtk.ToggleButton`（`set_mode(False)` 视觉上更稳），class `chip`。
- 点击 → `self.type = 'doc'` → `self.rebuild_view()` → `self.run_search(reuse=True)`，不重跑索引查询。
- `self.view` 为 `list of k` 或 `None`；`count()` 返回 `len(view)`；`fill()` 用 `self.view[self.top + j]`。
- 排序 `Gtk.MenuButton` + `Gtk.Popover` + 7 个 `Gtk.ModelButton`，当前项 `set_label('✓ ' + …)`。
- 结果 >400 时在 chip 条尾部追加两个建议按钮（`Gtk.Button`，class `chip`）。

## 风险

- `facets` 在全量上算，100 万条约 0.5s：>20 万时先返回 `facets: null`，前端显示 3 个骨架 chip，下一帧再取（见 `docs/07`）。
- `scope` 判断必须含文件夹自身（`folder == scope`）与子目录（前缀），否则「文件夹」类型的 scope 会漏。
- 视图是 `k` 的列表，`groups.mark(k)` 仍按原始 k 索引，不要用视图下标去查版本标签——这是最容易出错的一处。
