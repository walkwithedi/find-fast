# T10 · 折叠态

**状态**：待做　**优先级**：P2　**平台**：双　**依赖**：T03　**预估**：0.5 人日

## 目标

收起时窗口是一个 90px 的完整浮条：搜索框一行 + 右侧条目数。不是「高度 1px，靠 WM 兜底」。

## 为什么

`find_fast_gtk.py:1397` 的 `self.win.resize(self.size[0], self.size[1] if want else 1)` 把高度设成 1px。不同窗口管理器的最小高度不同，实测有环境把搜索框下半截裁掉。收起态是「随时待命」的状态，视觉残缺会让人以为程序坏了。

## 改动点

### GTK

1. `apply_layout()`：`resize(self.size[0], 90 if not want else self.size[1])`。
2. `EXPANDED_MIN`（150）保持；`on_configure` 里对小于 `EXPANDED_MIN` 的高度不记忆（现状已如此）。
3. 收起时隐藏：筛选条、列表区、状态栏、详情面板；显示 overlay 里的 `hint`（`共 N 项`）。
4. 收起态下 `entry` 仍可输入；有输入立即 `apply_layout()` 展开（`want_expanded()` 已含 `bool(text)`）。
5. 快捷键「收起为搜索框」（菜单项 + `Ctrl+Shift+Space` 或现有 accel）设置一个手动折叠标志，避免空文字时反复展开。

### Web

1. `.shell.folded { height: 90px }`；隐藏筛选条 / 结果区 / 状态栏；右侧显示 `#foldState`（`共 N 项`）。
2. 清空输入 300ms 后自动收起（仅在演示原型里；真实页面不需要，可加开关）。

## 验收

- [ ] GTK 收起后窗口高 90±2，搜索框完整可见（截图，含边框与圆角）
- [ ] 右侧显示 `共 128,441 项`
- [ ] 收起态输入 `pdf` → 立即展开且结果已出
- [ ] `Esc`（空文字）从展开 → 收起 → 隐藏，三态清晰
- [ ] 重新展开后高度回到收起前（不是默认 600）
- [ ] `grep -n "else 1" find_fast_gtk.py` 无命中
- [ ] 多 WM 验证：至少在 GNOME（Mutter）与一个平铺 WM（i3/sway）下不裁切

## 风险

- 部分 WM 在 `resize` 后会异步调整，需要 `GLib.idle_add` 二次校正高度。
- 收起时 `hint` 覆盖在搜索框右侧，注意不要挡住原生清除按钮（`margin_end: 30`）。
- Web 的折叠态是演示用，别在真实页面里做成「自动收起」打扰用户。
