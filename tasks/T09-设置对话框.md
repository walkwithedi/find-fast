# T09 · 设置对话框重排

**状态**：待做　**优先级**：P1　**平台**：双　**依赖**：T01　**预估**：1.5 人日

## 目标

一条长列表改成四分区，高频项在前；删掉已经没有意义的「列顺序」；保存路径与配置字段一个都不变。

## 为什么

现在「索引隐藏文件」这种高频开关要滚到中部才能看到，「列顺序」这种一次性配置却占了一屏；GTK 侧还把升级报告、唤起键全塞在同一屏。

## 分区

| 分区 | 内容 |
|---|---|
| 索引的文件夹 | 根目录列表（增删）、隐藏文件开关、搜索匹配路径开关 |
| 排除规则 | 名称规则与路径规则列表（增删） |
| 搜索 | 语法速查（只读）、结果上限、默认排序 |
| 升级 | 现有升级/回退面板入口（保持原逻辑） |

> 现有配置字段：`roots`、`exclude`、`hidden`、`match_path`。**不得增删**。新增的界面项（默认排序）只写 `ui_state`，不进 config。

## 改动点

### Web

1. `#settings` 结构改为：`.set-nav`（168px，四个按钮，`role="tab"`）+ `.set-body`（四个 `[role=tabpanel]`）+ 底部按钮区。
2. `renderSettings()` 拆成 `renderPane(name)`，切换时只重绘当前面板。
3. 删除「列顺序」面板与 `#setColumns`、`#colDefaults`、`colUp/colDown` 相关代码与文案键。
4. 升级入口从页头移入设置第四分区（保留 `#up-open` 的 id 与逻辑）。
5. `Esc` 关闭、`Ctrl+Enter` 保存、焦点陷阱（Tab 在对话框内循环）。

### GTK

1. `open_settings()` 改成 `Gtk.Dialog` + `Gtk.Stack` + `Gtk.StackSwitcher`（四页同名）。
2. 删除列顺序页与 `column_order/set_column_order/column_drop_ok` 相关回调。
3. 升级页复用现有 `upgrade_*` 方法，不改逻辑。
4. 快捷键记录控件（若有）留在「搜索」页底部。

## 验收

- [ ] 四分区切换无闪烁，当前分区高亮
- [ ] 「索引隐藏文件」「搜索匹配路径」在「索引」分区第一屏可见
- [ ] 「列顺序」相关 UI 与 localStorage 键全部消失（`grep -n "setColumns\|COL_KEY" find_fast.html` 无命中）
- [ ] 保存后 `~/.config/find-fast/config`（或对应路径）字段与 0.6.0 完全一致（`diff` 旧配置）
- [ ] 取消 / Esc 不写入配置
- [ ] 保存失败（例如根目录为空）时错误显示在按钮区上方，对话框不关闭
- [ ] 升级入口可打开升级面板，升级流程未被改动
- [ ] GTK 的 `Gtk.StackSwitcher` 可用键盘左右切换
- [ ] 对话框宽度 720，内容滚动，按钮固定在底部

## 风险

- 现有 `#setMsg`、`#setAnyway`（仍然保存）流程有较多分支，重排时不要重写这部分逻辑，只搬 DOM。
- GTK 的 `open_settings()` 里有大量局部变量引用 `self.*`，拆分页面前先确认每个控件的生命周期（切换页面不能销毁要保留状态的控件）。
- 删除「列顺序」后，`load_ui_state` 里对 `order` 的读取要容错（旧配置里有 `order` 字段时不能报错）。
