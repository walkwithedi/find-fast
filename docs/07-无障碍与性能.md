# 07 · 无障碍与性能

## 无障碍

目标：**WCAG 2.1 AA**。桌面工具不需要满足 AAA，但下面每一条都是硬要求，验收会抽查。

### 对比度

已实测（见 `docs/03`）：正文最低 4.7:1，图形最低 4.5:1，主按钮白字 6.2:1，深色下 4.78:1。**任何新加的颜色都要报出比值**，不达标的换成令牌。

### 结构语义

| 元素 | 角色 | 必须有的属性 |
|---|---|---|
| 搜索框 | `combobox` | `aria-expanded="true"` `aria-controls="list"` `aria-autocomplete="list"` `aria-activedescendant="opt-N"` `aria-label` |
| 列表容器 | `listbox` | `aria-label="搜索结果"` `tabindex="0"` |
| 结果行 | `option` | `aria-selected` `id="opt-N"`，行内文本要能被整句读出（名称 + 路径 + 大小 + 时间都在文本节点里） |
| 筛选 chip | `button` | `aria-pressed="true/false"`，计数作为文本一部分（`文档 5`） |
| 排序 | `button` | `aria-haspopup="menu"`；菜单 `role="menu"`，项 `role="menuitemradio"` + `aria-checked` |
| 状态栏 | `status` | `aria-live="polite"`，只在结果数变化时更新文本，不要每帧更新 |
| 菜单 | `menu` | 打开时焦点进第一项，`Esc` 关闭并还焦点 |
| 对话框 | `dialog` | `aria-modal="true"` `aria-labelledby`，用原生 `<dialog>` 或 GTK Dialog |
| 图标按钮 | `button` | `aria-label`；装饰图标 `aria-hidden="true"` |

### 焦点

- 所有可交互元素都有 `:focus-visible` 环（2px `--accent`，offset 1）。**禁止** `outline:none` 而不给替代。
- 焦点顺序 = 视觉顺序：应用条 → 搜索 → 筛选 → 排序 → 列表 → 详情按钮 → 状态栏。
- 对话框关闭后焦点回到触发控件；菜单关闭后回搜索框。
- 列表内用 `aria-activedescendant` 而不是移动真实焦点，保证输入不中断。

### 键盘

`docs/05` 的键位表即为验收依据。最低要求：不碰鼠标能完成「唤出 → 输入 → 选择 → 打开 → 定位 → 复制路径 → 关闭」。

### 动效与缩放

- `prefers-reduced-motion: reduce` 时所有过渡 ≤1ms，骨架 shimmer 停止。
- 浏览器 200% 缩放 / GTK 字号放大到 1.5 倍时：不出现横向滚动，行高自动增长（不要写死 `height:48px` 挡文字，用 `min-height`），两行文本不重叠。
- 触控目标 ≥32×32（图标按钮 34、chip 28 高 + 上下 padding 补足到 44 的点击区可用伪元素扩展）。

### 屏幕阅读器播报

- 输入 3 个字母后，状态栏播报 `N 个结果`（`aria-live="polite"`，延迟 300ms 合并）。
- 用 ↓ 切换选中时，靠 `aria-activedescendant` 让 SR 读该 option 的文本；不要额外加 `aria-live`，否则会双重播报。
- 扫描开始/结束播报一次，不要每 100ms 播报进度。
- 错误（正则语法）用 `role="alert"`，只播一次。

## 性能

### 预算

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 输入到结果上屏 | ≤120ms（本地索引，万级结果） | `performance.now()` 包住 fetch + 渲染，DevTools Performance |
| 选中切换 | ≤16ms（单帧） | 只改两行的 class，不重建列表 |
| 滚动 | 10 万结果下 ≥50fps | Chrome Performance 录制 3 秒滚动 |
| 首次渲染 200 行 | ≤50ms | `console.time` |
| GTK 滚动 | 每帧只填可见行（现状），滚动不掉帧 | 肉眼 + `fill()` 计时 |
| 内存 | 页面常驻 <80MB（10 万结果） | DevTools Memory |

### Web 侧必须做的

1. **只渲染视口附近**：首屏 200 行，滚动到距底 20 行再追加；不要一次渲染 5,000 行。
2. **选中只改两行**：`paintSel()` 里对比上一次的 `state.sel`，只 toggle 两个元素的 `aria-selected`，不要遍历全部行（原型已如此，别退化）。
3. **高亮只算返回的行**：`/api/search` 的 `limit` 就是渲染量，服务端只对这批行生成 `name_html`。禁止「先把全部结果高亮好再分页」。
4. **输入防抖 120ms**，并且 `AbortController` 取消上一次未完成的请求；响应乱序时用递增 `seq` 丢弃旧结果。
5. **不触发强制同步布局**：批量读 `offsetHeight` 再批量写；用 `requestAnimationFrame` 合并滚动回调。
6. **facets 昂贵时异步**：结果 >20 万条，先返回 `facets: null`，前端显示 chip 的骨架（3 个灰条），下一帧再取。

### GTK 侧必须做的

1. 保持「Store 只装可见行」的虚拟化：`fill()` 仍是 O(可见行数)，不要为了两行结构改成全量 model。
2. 行高固定 48，`measure_row_height()` 不再调用 `cell_get_size()`（每次滚动都量一次会掉帧）。
3. `fill()` 里生成 markup 的字符串拼接用局部变量与 `%` 格式化，避免每行创建 dict。
4. `scroll_to()` / `on_adj()` 里的重填用 `GLib.idle_add` 合并，保证一次滚动只填一次。
5. 高亮颜色按主题缓存一次，不要在每行里查 `Gtk.Settings`。

### 反例（提交前自查）

- 在 `renderList()` 里给每行 `addEventListener`（200 行 = 200 个监听）。
- 在 `scroll` 事件里 `querySelectorAll('.row')`。
- 每次输入都重建整个筛选条 DOM（只在计数变化时重绘，且用 `innerHTML` 一次赋值）。
- 在 GTK 里对全量结果算 facets（应该在后台线程算一次并缓存）。
