# 02 · 信息架构与布局

## 一条主线

```
想找文件 → 唤出 → 输两个字母 → 在候选里认出它 → 打开
         ↑ 0.1s      ↑ 0.3s        ↑ 1-3s        ↑ 0.1s
```

界面只服务这条线。任何不在这条线上、又不省时间的元素，都不该常驻。

## 四层结构

从上到下，四层各自有明确职责，不重叠：

```
┌──────────────────────────────────────────────────────────────┐
│ ① 应用条  30px   标识 · 版本 ·（外观 / 帮助 / 设置）           │  Web 才有；GTK 用原生标题栏
├──────────────────────────────────────────────────────────────┤
│ ② 搜索层  65px   搜索框 44px（主角）· 清除 · 快捷键提示        │
│           ▔▔ 2px 扫描进度（绝对定位，不占布局）                │
├──────────────────────────────────────────────────────────────┤
│ ③ 收敛层  38px   类型 chip + 计数 ｜ 缩小范围 ｜ 排序          │  仅在有查询且有结果时出现
├──────────────────────────────────────────────────────────────┤
│ ④ 结果层  弹性   列表 48px/行                   详情 340px    │  详情仅在宽 ≥1080 时出现
│                  ├ 选中行左侧 3px 标记                         │
│                  └ 空状态 / 骨架 / 无结果时覆盖列表区          │
├──────────────────────────────────────────────────────────────┤
│ ⑤ 状态层  28px   N 个结果 · 耗时 ｜ 键位提示 ｜ ● 索引状态     │  唯一的报数处
└──────────────────────────────────────────────────────────────┘
```

层高固定（除结果层），所以「输入时界面不会跳」。扫描进度、toast、菜单都是绝对定位浮层，不参与布局计算。

## 各层职责

| 层 | 只负责 | 不负责 |
|---|---|---|
| ① 应用条 | 品牌/版本、外观切换、帮助入口、设置入口 | 搜索、结果、状态 |
| ② 搜索层 | 输入、清除、语法错误就地提示、扫描进度 | 结果计数（那是⑤） |
| ③ 收敛层 | 按类型/位置缩小范围、排序 | 选中、打开 |
| ④ 结果层 | 候选列表、选中、预览、行内操作入口 | 全局动作（重新扫描属于①的更多菜单） |
| ⑤ 状态层 | 结果数、耗时、索引状态、键位提示 | 重复报数 |

**唯一数据源规则**：结果数只在⑤出现。③的 chip 上带分类计数（不同维度，允许），但不得再出现「共 N 个结果」的第二处。

## 栅格与尺寸

| 项 | 值 | 说明 |
|---|---|---|
| 窗口内边距 | 左右 14px | 搜索框、筛选条、列表左缘对齐同一条 14px 线 |
| 搜索框 | 高 44，圆角 12，内边距 左12/右10 | 唯一的 44px 高控件 |
| 结果行 | 高 48，左内边距 15，右 12 | 图标列 20，间距 11，信息列 1fr，元信息列 116 |
| 详情面板 | 宽 340，内边距 16 | 与列表用 1px 分隔线，不用阴影 |
| 状态栏 | 高 28 | 字号 11.5，等宽数字 |
| 对话框 | 宽 720，最大高 82vh | 内容滚动，按钮固定在底部 |

三列对齐规则（最重要的一条）：**行内的图标、名称、右侧元信息，必须在所有行上形成三条竖线**。名称列左缘与搜索框文字左缘不必对齐，但行与行之间必须严丝合缝。

## 断点

| 宽度 | 变化 | 理由 |
|---|---|---|
| ≥1080 | 完整：列表 + 340px 详情 | 默认 |
| 1080–860 | 隐藏详情面板；操作回到右键菜单 + 键盘 | 列表优先，560px 以下单行信息放不下两列 |
| 860–720 | 筛选条改为可横滑；状态栏隐藏中部键位提示 | 保住结果数与索引状态 |
| <720 | 隐藏右侧时间，只留大小；路径只显示末级目录 | 再窄就只剩文件名，仍可用 |
| <560 | 应用条只留标识与设置 | 不为手机设计，只保证不破版 |

GTK 侧只有一条：**宽度 <960 隐藏详情面板**，其余不变（桌面窗口很少更窄，且 GTK 无法做 CSS 断点）。

## 折叠态（仅「有全局唤起键」时）

窗口收起成 90px 的浮条：应用条隐藏，只留搜索框一行 + 右侧条目数。

```
┌──────────────────────────────────────────────┐
│ 🔍 搜索文件名或所在文件夹…        ↑↓ 选择  ⋯ │  90px
└──────────────────────────────────────────────┘
```

- 输入即展开（回到上次高度），清空后 300ms 自动收起（可配置，默认开启）。
- 收起时不显示结果数以外的任何状态；索引状态收进右侧条目的 tooltip。

## 与旧结构的一一对应

| 旧 | 新 | 处理 |
|---|---|---|
| `.bar`（搜索 + 齿轮 + 排序 select） | ② 搜索层 + ③ 收敛层右侧 | 排序从 `<select>` 变胶囊按钮 + 菜单 |
| `.help` 常驻长段 | `?` 快捷键/语法面板 | 删除常驻，改为按需 |
| `.actions`（打开/定位/复制/重扫） | ④ 详情面板 + 右键菜单 | 重新扫描移入「更多」 |
| `<table>` 五列 + 表头 | ④ 两行行结构 | 表头删除；排序进③ |
| 行尾「定位」按钮列 | 详情面板 | 列删除 |
| `#status` + 页脚 `#index` | ⑤ 单行状态 | 合并 |
| GTK TreeView 四列 + 表头 | 单列两行渲染 | 列头排序删除 |
| GTK `resize(w,1)` 折叠 | 90px 浮条 | 修 |
